--- первый cout
1. [Исключение] Обращение к std::cout << " test : "
   Обоснование: Работа со стандартным потоком может сгенерировать std::ios_base::failure, если установлен флаг failbit/badbit, или std::bad_alloc при ошибке буферизации.
2. [Исключение] Вызов метода person.name()
   Обоснование: Тело пользовательского метода может содержать логику, генерирующую любые исключения.
3. [Исключение] Возврат результата name() по значению
   Обоснование: Создание временного объекта (например, std::string) может выбросить std::bad_alloc при выделении памяти.
4. [Исключение] Неявное приведение типа результата name()
   Обоснование: Если тип, возвращаемый методом person.name(), не имеет собственной перегрузки operator<<, но имеет оператор неявного приведения к другому типу (например, operator std::string()), компилятор вызовет его. Вызов этого оператора преобразования может сгенерировать исключение (например, std::bad_alloc при выделении памяти для новой строки).
5. [Исключение] Вызов operator<< для результата name()
   Обоснование: Перегруженный оператор вывода для пользовательского типа может бросить исключение при форматировании.
6. [Исключение] Вызов operator<< для символа '\n'
   Обоснование: Аналогично п.1, риск ошибки I/O потока.
7. [Исключение] Уничтожение временного объекта от name()
   Обоснование: Если деструктор возвращаемого типа не помечен как noexcept, его вызов в конце выражения может бросить исключение.

--- блок if
8. [Исключение] Вызов метода person.grade()
   Обоснование: Пользовательский метод может выбросить исключение.
9. [Исключение] Возврат результата grade()
   Обоснование: Копирование возвращаемого значения может бросить исключение (например, нехватка памяти).
10. [Исключение] Неявное приведение типов при сравнении grade() == 10
    Обоснование: Если grade() возвращает пользовательский тип, компилятору может потребоваться привести его к int (вызов оператора приведения типа), либо наоборот — неявно сконструировать временный объект из литерала 10 (вызов CustomGrade(int)). Если этот конструктор или оператор приведения содержит логику валидации или выделяет память, он может выбросить исключение.
11. [Исключение] Оценка выражения operator==  
    Обоснование: Если оператор сравнения перегружен для пользовательского типа, он является обычным вызовом функции и может бросать исключения.
12. [Исключение] Оценка выражения operator||
    Обоснование: Если логическое ИЛИ перегружено для пользовательских типов, оно может генерировать исключения.
13. [Ветвление] Short-circuit оператора ||
    Обоснование: Нормальное ветвление. Если левая часть (grade() == 10) равна true, правая часть условия игнорируется.
14. [Исключение] Вызов метода person.salary()
    Обоснование: Выполняется только если не сработало первое условие. Риск генерации исключения внутри метода.
15. [Исключение] Неявное приведение типов при сравнении salary() > 1'000'000
    Обоснование: Аналогично п.10. Если salary() возвращает пользовательский класс (например, Money), для сравнения может потребоваться неявное преобразование литерала 1'000'000 в этот тип. Конструктор преобразования (например, Money(int)) может сгенерировать исключение перед самим сравнением.
16. [Исключение] Возврат результата salary()
    Обоснование: Копирование/создание временного объекта для возвращаемого значения.
17. [Исключение] Оценка выражения operator>
    Обоснование: Аналогично п.11, перегруженный оператор может бросить исключение.
18. [Исключение] Приведение результата к типу bool
    Обоснование: Условие оператора if требует типа bool. Если используется пользовательский operator bool(), он может бросить исключение.
19. [Исключение] Уничтожение временных объектов условия
    Обоснование: В конце условия if уничтожаются объекты от grade() и salary(). Их деструкторы могут выбросить исключения.
20. [Ветвление] Условный оператор if
    Обоснование: Явное ветвление потока управления на true и false на основе результата проверки.

--- блок if, ветка true
21. [Исключение] Вызов метода person.id()
    Обоснование: Обращение к методу в ветке true может бросить исключение.
22. [Исключение] Возврат результата id() по значению
    Обоснование: Риск исключения при вызове копирующего конструктора.
23. [Исключение] Неявное приведение аргументов при вызове save(...)
    Обоснование: Функция save может ожидать аргумент типа, отличного от того, который возвращает person.id(). Например, если id() возвращает size_t, а save принимает std::string или UserId. В этом случае компилятор неявно вызовет конструктор преобразования для создания нужного типа из результата id(). Этот конструктор может бросить исключение (например, нехватка памяти или ошибка парсинга) еще до того, как управление перейдет внутрь функции save.
24. [Исключение] Вызов функции save(Status::success, ...)
    Обоснование: Сама функция сохранения может выбросить исключение (ошибка записи, разрыв соединения и т.д.).
25. [Исключение] Уничтожение временных объектов ветви true
    Обоснование: Деструктор результата id() или временно сконвертированных аргументов может бросить исключение при выходе из блока.

--- блок if, ветка false
26. [Исключение] Вызов метода person.id()
    Обоснование: Обращение к методу в ветке false может бросить исключение.
27. [Исключение] Возврат результата id() по значению
    Обоснование: Риск исключения при копировании объекта.
28. [Исключение] Неявное приведение аргументов при вызове save(...) (ветка false)
    Обоснование: Полностью аналогично п.23. Риск генерации исключения при неявном конструировании аргументов, требуемых сигнатурой функции save, из типа, возвращаемого id().
29. [Исключение] Вызов функции save(Status::failure, ...)
    Обоснование: Аналогично п.24, генерация исключения внутри функции сохранения.
30. [Исключение] Уничтожение временных объектов ветви false
    Обоснование: Риск исключения в деструкторах очищаемых объектов (результата id() и аргументов) перед выходом из функции.
